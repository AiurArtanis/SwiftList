# Project Development and Compilation General Specifications

When using the project's toolchains, compiling code, or performing development, the AI assistant must strictly adhere to the following guidelines:

1. **On-Demand and Narrow-Scope Compilation**
   * Compile projects only when absolutely necessary.
   * **Blind compilation of the entire solution (e.g. `dotnet build *.sln` or `*.slnx`) is strictly prohibited**. You must compile only the specific subproject to which the modified files belong (for example: if only UI is modified, compile only `dotnet build App\App.csproj`).
   * This maximizes compilation efficiency and completely avoids DLL file lock conflicts caused by needlessly compiling other unmodified projects (like Service or Core), thereby **guaranteeing that the background service is never stopped/restarted without modification to the service or core libraries**.

2. **Compiling Frontend/UI App and Plugin Projects**
   * Before compiling, the corresponding running process of the frontend App must be terminated to release the binary file lock.
   * Since the App may run with Administrator privileges, the termination command must be executed with Administrator privileges (`runas` elevation) to avoid "Access is denied" errors. Example command (replace `<AppExecutableName>`):
     ```powershell
     powershell -Command "Start-Process taskkill -ArgumentList '/f /im <AppExecutableName>.exe' -Verb RunAs -WindowStyle Hidden"
     ```

3. **Compiling Core Library (Core) and Background Service (Service) Projects**
   * **CRITICAL ORDER**: Before compiling Core or Service, you **MUST terminate the frontend App process FIRST**. If the App is still running, it will immediately detect the loss of connection and automatically restart the hook subprocess (`SwiftList.Service.exe`), rendering any subsequent service process termination useless and keeping the DLL locked.
   * Both standard and Administrator-elevated `taskkill` commands must be used to ensure the App is fully stopped under all privilege levels.
   * Complete sequence of commands to release all DLL locks:
     ```powershell
     # 1. Kill the frontend App first (standard & elevated)
     taskkill /f /im SwiftList.App.exe
     powershell -Command "Start-Process taskkill -ArgumentList '/f /im SwiftList.App.exe' -Verb RunAs -WindowStyle Hidden"

     # 2. Stop the Windows background service
     powershell -Command "Start-Process sc -ArgumentList 'stop SwiftListService' -Verb RunAs -WindowStyle Hidden"

     # 3. Kill the IPC hook subprocess
     powershell -Command "Start-Process taskkill -ArgumentList '/f /im SwiftList.Service.exe' -Verb RunAs -WindowStyle Hidden"
     ```

4. **No Unauthorized Commits**
   * Never execute `git commit` without authorization. All code changes must be reviewed and submitted under the explicit instructions of the user.
   * **Commit Message Standard**: When the user authorizes submission, all commit messages must be written in **English**.

5. **Launch and Debug (App Launching Method with Dependencies)**
   * When launching an App containing external dependencies, to prevent crashes due to incorrect current working directories failing to load dependencies, you must explicitly specify the output directory generated by the program as the working directory.
   * **For direct user local launching**, the recommended concise command is:
     ```powershell
     powershell -Command "Start-Process -FilePath '<AppOutputPath>\<AppExecutableName>.exe' -WorkingDirectory '<AppOutputPath>'"
     ```
   * **For the AI assistant launching in the background agent and requiring the process to keep running on the desktop**, you must append a wait mechanism to prevent recycling (you can omit `-FilePath` and `-NoNewWindow` flags and write in the simplest form):
     ```powershell
     powershell -Command "Start-Process <AppOutputPath>\<AppExecutableName>.exe -WorkingDirectory <AppOutputPath> -Wait"
     ```

6. **Strict Code File Line Limit (Modularization & Decoupling)**
   * All `.cs` and `.xaml` code files must be strictly kept under **300 lines**.
   * Before every compilation/build, you must check the line counts. If any file exceeds 300 lines, it must be modularized and decoupled.
   * **Do not use `partial` classes or partial views as a shortcut to bypass this limit**. Instead, perform structural decoupling by extracting clean helper classes, utilizing C# extension methods, or grouping logical subcomponents into subfolders.

7. **Clean File Naming and Directory Namespace Hierarchy**
   * Do not create multi-dot source code files such as `aa.bb.cs` or `SomeFeature.Helper.cs`.
   * Instead, strictly use subdirectories and nested namespace hierarchies (e.g., place the helper in `SomeFeature/Helper.cs` and match it with the nested namespace `SwiftList.SomeFeature`). This keeps filenames simple, intuitive, and standard.
