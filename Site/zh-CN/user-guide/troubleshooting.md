# 故障排查

## 全局热键没有反应

1. 先看**设置 → 运行状态**——如果后台服务没有运行，重装或重启它通常能解决索引相关的问题，但呼出
   热键本身是由 App 进程处理的，不是服务，所以这只是一个次要排查项。
2. 如果当前前台应用是以管理员身份运行的，而 SwiftList 不是，Windows 会阻止低权限进程向它发送输
   入。可以在**设置 → 通用 → 系统**里启用**以管理员权限启动**，或者手动以管理员身份运行一次
   SwiftList 来确认是否是这个原因。
3. 检查[进程黑名单](./settings/hotkeys-page#process-blacklist)——如果前台应用的可执行文件名
   被(有意或无意地)加入了黑名单，SwiftList 的全局热键在它处于前台时会被刻意放行、不做拦截。

## 搜索结果看起来过时了

本地磁盘是通过 USN 日志近乎实时更新的。如果还是有内容看起来不对(刚创建的文件没出现，或者已删除
的文件还在)，可以到**设置 → 索引 → 本地驱动器**(或**网络驱动器**)对相应磁盘执行**重建索引**。

## 网络驱动器好像一直不刷新

网络共享没有本地 NTFS 卷那种可以监听的变更日志，所以是按计划定时重新扫描的。到**设置 → 索引 →
网络驱动器**检查该驱动器的**刷新模式**——如果是**手动**，就不会自动更新，改成定时刷新，或者直接
点**重建索引**手动刷新一次。

## 预览窗口显示不对/被裁切

理论上不应该发生——SwiftList 会自动把 QuickLook 预览窗口的位置和大小钳制在当前显示器的可用区域
内。如果还是看到裁切，可以先到**设置 → 通用 → 预览窗口 → 重置预览窗口设置**排除掉手动设置了异常
宽高值的可能，并确认使用的是最新版本。

## 某个文件/文件夹完全搜不到

- 检查它是否被排除了——**设置 → 索引 → 排除规则**支持精确路径、glob 通配符和正则表达式三种方式，
  任何一种都有可能无意中命中它。
- 检查它所在的磁盘是否在**设置 → 索引 → 本地/网络驱动器**里被启用。

## 还是没解决?

在提交 GitHub issue 之前，先看看
**[设置 → 运行状态](./settings/service-status)** 里 **Service**、**App**、**Hook** 三个日志
Tab——搜索框可以按关键词过滤，等级下拉框可以按严重程度过滤。
